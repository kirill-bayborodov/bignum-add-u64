# `bignum_add_u64` standard benchmark profile

## Purpose

This companion document describes `profiles/bignum_add_u64_standard.json`, the eight-profile deterministic regression matrix for adding scalar `3` to a fixed-capacity little-endian bignum. The manifest is consumed by `benchmark-framework`; it does not alter the public arithmetic contract.

## Schema and field semantics

The top-level `schema_version` is the framework manifest version. Each object in `profiles` has the following fields:

| Field | Meaning | Values used here |
|---|---|---|
| `id` | Stable report identifier; it is used to match C11 and ASM samples. | Addition-specific kebab-case identifiers. |
| `input_kind` | Logical input family generated by the adapter. | `zero`, `nonzero`, or `mixed`. |
| `operation_kind` | Adapter operation selector. | `add_u64` for arithmetic profiles; `mixed` for the mixed workload. |
| `measure_mode` | Whether setup is included in timing. | `kernel-only` or `end-to-end`. |
| `size_profile` | Logical operand length vocabulary. | `one`, `quarter`, `half`, `variable`, or `near-capacity`. |
| `capacity_profile` | Capacity regime used by the workload. | `normal` or `near-capacity`. |

The adapter maps `one` to one word, `quarter` to one quarter of `BIGNUM_CAPACITY`, `half` to one half, and all other sizes to the full capacity. It generates deterministic nonzero words from the manifest seed and keeps the most significant generated word nonzero.

## Profile coverage

The matrix covers a zero-source end-to-end case, one-word and quarter/half-word kernel cases, variable-size end-to-end cases, a mixed workload, and near-capacity kernel/end-to-end cases. The `add_u64` operation adds scalar `3`; the mixed profile uses the framework's mixed metadata while the adapter still executes the documented add-u64 callback.

## Validation and failure handling

Before callbacks run, the adapter requires non-NULL `input_kind`, `operation_kind`, `measure_mode`, `size_profile`, and `capacity_profile` strings. Only `add_u64` and `mixed` operation kinds are accepted. A validation failure is an input error and must not be reported as a successful arithmetic sample. The checksum includes all result words, normalized logical length, and iteration number so compiler elimination or stale output cannot silently produce a valid-looking benchmark.

## Reproducible commands

Run the C11 baseline:

```sh
make bench_matrix CONFIG=release USE_ASM=no BENCH_MATRIX_PROFILE=benchmarks/profiles/bignum_add_u64_standard.json BENCH_MATRIX_REPETITIONS=3 BENCH_MATRIX_ITERATIONS=100000 BENCH_MATRIX_MT_TOTAL_ITERATIONS=200000 BENCH_MATRIX_WARMUP=1000 BENCH_MATRIX_DATA_COUNT=4 BENCH_MATRIX_TIMEOUT_SECONDS=60
```

Run the ASM implementation with the identical manifest and counters:

```sh
make bench_matrix CONFIG=release USE_ASM=yes BENCH_MATRIX_PROFILE=benchmarks/profiles/bignum_add_u64_standard.json BENCH_MATRIX_REPETITIONS=3 BENCH_MATRIX_ITERATIONS=100000 BENCH_MATRIX_MT_TOTAL_ITERATIONS=200000 BENCH_MATRIX_WARMUP=1000 BENCH_MATRIX_DATA_COUNT=4 BENCH_MATRIX_TIMEOUT_SECONDS=60
```

Compare `ns_per_call` by identical profile ID and mode. A valid comparison requires successful samples and matching workload fingerprints; one-word fixed-overhead cases should be interpreted separately from larger arithmetic kernels.
